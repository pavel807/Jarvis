# Jarvis — голосовой ассистент на Rust

Локальный голосовой ассистент для macOS, Linux и Windows: wake word → команды → ответы локальной LLM.
Работает полностью офлайн (кроме первого скачивания моделей).
Глубже всего системная интеграция на macOS; на Linux и Windows всё, что
завязано на систему, идёт через платформенный слой (`platform/`) со своими
механизмами у каждой ОС — и честным отказом там, где механизма нет.

## Архитектура

```
Cargo workspace
├── crates/jarvis-core   — движок: wake word, STT, TTS, LLM, команды, события
├── crates/jarvis-cli    — headless-запуск из терминала
└── app/                 — GUI (Tauri 2 + Svelte 5)
    ├── src/             — страницы интерфейса
    └── src-tauri/       — бэкенд приложения (трей, IPC, обучение wake word)
```

Подсистемы:
- **Wake word** — RustPotter (NN-модель `.rpw`), обучение прямо из интерфейса.
- **STT** — **FastConformer-Hybrid Large RU** (NVIDIA, ~115М параметров,
  гибрид CTC + RNN-T, словарь 1024 SentencePiece Unigram, CC-BY-4.0) —
  **собственная реализация на candle** (`asr/`), бит-в-бит сверенная с
  ONNX-эталоном (`fc_verify`: mel/энкодер/декодеры поэтапно, Δ~3e-6):
  mel-фронтенд (окно и фильтрбанк — из весов чекпоинта), маски хвостового
  кадра из графа эталона, depthwise-субдискретизация 8×, 17 Conformer-блоков
  с rel-pos attention, декодер RNN-T (предсказатель LSTM 640 + joint).
  **Считается на CPU (FP32, без квантизации)**: замер fc_bench показал, что
  Metal на этих размерах тратит фиксированные ~720 мс на dispatch командных
  буферов, CPU (Accelerate gemm) — 98 мс энкодера; команда распознаётся за
  ~150 мс (RTF 0.04). Metal включается `JARVIS_ASR_DEVICE=metal`. Декодер —
  настройка `asr_decoder`: `rnnt` (по умолчанию, WER 8.3% на say-наборе и
  3.3% на голосах Silero), `ctc`, `ctc_beam` — beam search со словарём Jarvis
  (триггеры команд + их русские формы произношения). Веса конвертируются из
  оригинального `.nemo` чекпоинта NVIDIA скриптом
  `tools/convert_fastconformer.py`. Pre-roll 500 мс: первый слог команд не
  теряется. ONNX Runtime и transcribe-rs не используются.
- **TTS** — Silero v5 (v5_cis_base, FastPitch + Vocos) на **candle**, CPU:
  29 русских голосов, RTF ~0.03. Нейро-ударитель: словарь ударений + ё,
  char-level RoFormer (candle) для незнакомых слов и контекстный резолвер
  омографов ruaccent (DistilBERT, candle) — «замок/стоит/дела/мука» читаются
  по смыслу фразы. ONNX Runtime в TTS-пути не используется. Кэш синтеза
  с LRU-очисткой.
- **LLM** — два бэкенда за общим интерфейсом (настройка `llm_backend`):
  **uzu** (движок Mirai/trymirai, MIT, чистый Rust + Metal, только macOS;
  модели Qwen3.5 0.8B–9B в 4/8-бит качаются из каталога Mirai в
  `~/.cache/mirai`, по умолчанию `qwen3.5-2b-mirai-m`) и **candle**
  (собственные реализации: Qwen3.5-0.8B — гибрид Gated DeltaNet + gated
  attention, альтернатива MiniCPM5-1B-ru, Llama-архитектура; веса BF16
  safetensors в `models/`). Стриминг ответа в TTS по предложениям, префиксный
  KV-кэш между ходами на обоих бэкендах, контекст диалога в пределах
  follow-up сессии (чистится при возврате к wake word). Если uzu недоступен
  (нет сети для каталога, модель не скачалась) — автоматический откат на
  candle.
- **Понимание просьбы** — роутер (`router.rs`) решает, действие это или
  разговор, и делает это скорингом, а не списком префиксов. Однозначный глагол
  («открой», «поставь», «сверни») — действие; вопросительный зачин («сколько»,
  «почему», «что такое»), абстрактный объект («смысл», «совесть», «стих») или
  просьба о переводе — разговор. Раньше «покажи мне смысл этой фразы»,
  «сколько у меня будет пенсия» и «температура кипения воды» уезжали в
  action-ветку, где принудительный prefill `<tool>{"name":"` лишал модель права
  ответить текстом — она обязана была выдумать инструмент. Теперь уверенность
  роутера видна вызывающему коду: ниже порога (`FORCE_TOOL_CONFIDENCE`) prefill
  не форсируется, и текстовый ответ — нормальный исход.
- **Бюджет промпта** — цена промпта измеряется в токенах (`prompt_budget`),
  потому что модель читает его на каждом шаге. Чат-промпт — ~135 токенов,
  action-промпт с ядром инструментов и каталогом команд — ~1180, а с нужными
  срезами — до ~1390 в худшем случае (против 1662 у старого промпта со всеми
  32 инструментами сразу). Инструменты
  собраны в срезы (`TOOL_SLICES` в `router.rs`): ядро (shell, файлы, интернет,
  приложения) есть всегда, а окна, таймеры, сообщения, музыка и задачник
  добавляются только когда слова просьбы этого требуют. Потолки зафиксированы
  тестом `crates/jarvis-core/tests/prompt_budget.rs` на реальном токенизаторе.
  Замер вручную:
  `JARVIS_HOME=. cargo run --release --example prompt_size -p jarvis-core`.
- **Долговременная память о пользователе** (по логике OpenJarvis): после
  диалога фоновый экстрактор вычленяет устойчивые факты (предпочтения,
  проекты, ограничения) и складывает в `memory.json`; при следующих ответах
  самые свежие факты подмешиваются в системный промпт. Голос: «запомни, что…»
  (инструмент `remember`), «забудь» — через список фактов.
- **Планировщик задач** (по логике OpenJarvis: cron/interval/once): голосом
  «каждое утро в 8 собери новости и дай сводку» → `schedule_add`. Задача
  выполняется сама в изолированном диалоге, ответ проговаривается и приходит
  в уведомлении. Хранение — `schedule.json`, поллер проверяет раз в 20 с.
- **Telegram-канал**: впиши токен бота и разрешённые chat_id в
  `settings.toml` (`telegram_bot_token`, `telegram_chat_ids`) — Джарвис
  отвечает в Telegram тем же мозгом, с памятью и датой; чужие чаты молчат.
- **MCP-инструменты**: внешние серверы Model Context Protocol из
  `settings.toml` (`[[mcp_servers]]` name/cmd/args) появляются у модели как
  `mcp_call {"server":…,"tool":…,"args":{…}}`; упавший сервер не роняет
  остальные, инструменты доступны движку на любой ОС.
- **Память тем** — помнит последние темы отдельно от контекста диалога. Если
  разговор ушёл в сторону, «мы это забыли» или «о чём говорили» возвращает
  Джарвиса к незакрытой теме: прошлый вопрос и ответ уходят в историю, модель
  продолжает с того места, где остановилась.
- **Исполнение и верификация** — каждый инструмент имеет контракт в
  реестре (`agent.rs`): уровень риска, таймаут, положенное постусловие.
  После исполнения Verification Engine проверяет фактический результат:
  файловые записи перечитываются (file_write/file_append/file_edit),
  скриншот обязан существовать и быть непустым, громкость читается обратно
  из системы, выход приложения подтверждается поллингом процесса. Успех
  без подтверждения не объявляется: неподтверждённое — «не подтвердилось»,
  а не «сделано». Звук-подтверждение команды играется только после
  успешного исполнения; «стоп» никогда не превращается в «Готово»; ошибки
  LLM дублируются голосом; вердикт роутера и неразобранные tool-вызовы
  публикуются событиями RouterVerdict/ToolParseFailed для диагностики.
- **Команды** — `commands.toml` с hot-reload, дословный матчинг: триггер в
  начале фразы срабатывает мгновенно, без LLM. Движок детерминированно
  выполняет только системные команды (`stop`/`exit`), остальные — через LLM.
  Если фраза не совпала дословно, команды видит LLM: она понимает просьбу по
  смыслу («включи что-нибудь бодрое») и выполняет подходящую команду через
  инструмент `run_command`. В значении действия можно использовать параметры
  `{...}` — модель подставит их из запроса, так что одна универсальная команда
  покрывает целый класс просьб:
  `action_value = "https://music.yandex.ru/search?text={query}"` → «включи
  на яндекс музыке {что угодно}» (для поиска также работает слот `{}`).
  Сжатый каталог (имя, триггеры, действие) попадает в контекст LLM, чтобы она
  выбирала команду по смыслу.
- **Работа с файлами и рабочий цикл** — ассистент не только открывает, но и
  читает и правит: `file_read` (по строкам, с `offset`/`limit` и номерами —
  модель видит, на что ссылаться), `file_search` (поиск строк по дереву с
  контекстом), `file_glob` (файлы по маске имени), `file_edit` (замена
  фрагмента: текст для `old` берётся из чтения, а не из памяти — если фрагмент
  не найден или неоднозначен, правка отклоняется, а не «удаётся» молча),
  `file_append`, `file_write`. Рабочая папка одна на весь цикл: относительные
  пути считаются от неё, а `cd` внутри `shell` её меняет — поэтому цепочка
  «зайди в проект, найди место, поправь, проверь» собирается. Служебные
  каталоги (`.git`, `node_modules`, `target`) при обходе пропускаются, обход
  не уходит выше 12 уровней и не читает файлы больше 2 МБ.
- **Системная интеграция** — таймер и будильник (в процессе Джарвиса,
  рингтон и отмена голосом), окна программ («сверни хром», «во весь экран» —
  русские названия приложений понимаются), запуск/закрытие приложений, браузер,
  громкость, яркость, скриншот, блокировка, сон, буфер обмена, музыка.
  Выбор действия делает LLM (tool-calling), исполнение — **платформенный слой**
  (`platform/`): один интерфейс, у каждой ОС свой исполнитель:
  - **macOS** — AppleScript/osascript и `open`; «Музыка» и вкладки браузеров
    с проверкой, что музыка реально играла; CoreAudio — громкость;
    `screencapture` — скриншот; iMessage, «Заметки», «Календарь».
  - **Linux** (X11) — окна: wmctrl (запасной — xdotool); приложения:
    `.desktop`-файлы + gtk-launch; музыка: playerctl (MPRIS); громкость:
    pactl (запасной — amixer); яркость: brightnessctl (запасной — xrandr);
    скриншот: gnome-screenshot / spectacle / scrot / grim / import;
    блокировка: loginctl; сон: systemctl; уведомления: notify-send;
    буфер: wl-copy или xclip/xsel. На Wayland управление окнами недоступно
    (честный отказ), но музыка, громкость, буфер и скриншот (grim) работают.
    Элементы интерфейса (ui_read/ui_click/ui_type/ui_menu) — **AT-SPI2**
    (`auto/atspi_linux.rs`): то же чтение экрана текстом и действия по
    именам элементов, что на macOS, работает на X11 и Wayland (GTK/Qt
    отдают дерево через at-spi2-core); клики и Enter по координатам
    выполняют xdotool (X11) или ydotool (Wayland).
  - **Windows** — PowerShell 5.1 (есть в системе): окна — user32
    (ShowWindow/SetForegroundWindow); музыка — SMTC, а если API недоступен —
    медиа-клавиши с честной формулировкой «отправил команду»; громкость —
    CoreAudio; яркость — WMI; скриншот — .NET (весь виртуальный экран);
    блокировка и сон — rundll32; уведомления — NotifyIcon; буфер —
    Get-Clipboard.
  Любой текст в скрипты уходит только через base64 — ни инъекции, ни проблем
  с кодировкой cp1251. Отсутствует утилита или API — ассистент говорит, чего
  не хватает, а не выдаёт ложный успех. Навыки Apple-экосистемы (iMessage,
  «Заметки») на других ОС честно отклоняются.

  Оптимизации горячих путей: кэш списка приложений и разрешённых имён
  (macOS), кэш `Get-StartApps` (Windows, на сессию), кэш проверки наличия
  команды в PATH; убитый по таймауту процесс дожидается (`wait`), чтобы не
  копить зомби; уведомление на Windows запускается отдельно и не тормозит
  ответ.
- **AppleScript в процессе приложения** — скрипты выполняет `NSAppleScript`
  внутри Джарвиса, а не порождённый `osascript` (внешний процесс остался
  запасным путём и отключается переменной `JARVIS_APPLESCRIPT=osascript`).
  Это важно из-за разрешений: macOS привязывает «Автоматизацию» к тому, кто
  спросил, поэтому запрос теперь приходит от самого Джарвиса — «Джарвис хочет
  управлять „Музыкой“» — и его достаточно выдать один раз. Раньше внешнему
  `osascript` система молча отвечала отказом (`privilege violation`, -10004),
  и пользователь не понимал, что именно разрешать. Заодно исправлена паника
  objc2 на NULL-ответе: отказ системы теперь становится внятным сообщением,
  а не падением приложения.
- **Музыка** — «поставь на паузу», «останови музыку», «следующий трек».
  На macOS работают и нативная «Музыка», и вкладка браузера (Яндекс Музыка,
  YouTube): Джарвис смотрит, что реально играет, и управляет источником звука.
  Успех подтверждается чтением состояния плеера до и после команды —
  AppleScript `pause` завершается успешно и на пустой «Музыке», поэтому без
  проверки ассистент отвечал «Поставил на паузу», а музыка играла дальше.
  Ничего не играет — так и говорит. Управление вкладкой требует разрешения
  «Автоматизация» для Jarvis и включённого «Разрешить JavaScript из
  AppleScript» в браузере; без них звучит честная причина, а не ложный успех.
  На Linux — playerctl (MPRIS), проверка состояния до/после такая же. На
  Windows — SMTC; если он недоступен, управление уходит медиа-клавишами, и
  ответ честно говорит «отправил команду» — выдать это за подтверждённый
  успех Джарвис не может и не станет.

### Озвучка текста (TextNormalizer)

На пути LLM/сообщение → TTS стоит конвейер (`tts_normalizer.rs`): Markdown
превращается в устную речь (заголовки — предложениями, списки — «Пункты: …»,
ссылки — только текст, длинные фрагменты кода сворачиваются в «фрагмент
кода»), затем подставляются произношения (CPU → «си-пи-ю», Premiere Pro →
«премьер про», версии 2.1.3 → «два точка один точка три»), затем числа, даты
и единицы измерения (`text.rs`). Словарь произношений расширяется без
пересборки: файл `pronunciations.toml` в каталоге данных (`JARVIS_HOME`):

```toml
[pronunciations]
"Моя программа" = "моя программа"
"Obsidian" = "обсидиан"
```

Голосовой профиль «Джарвис» — мужской тембр, спокойная подача: голос
подбирается прослушиванием примера `voice_compare` (все мужские голоса v5
на одинаковых фразах, WAV в `build/voice_compare/`), затем фиксируется в
`settings.toml` (`tts_voice`, рекомендуемая скорость `tts_speed = 0.9`).
Имя «Jarvis» в любом тексте всегда произносится «Джарвис».

## Требования

Общее:
- Rust (stable, edition 2024), [bun](https://bun.sh)
- ~8 ГБ RAM под модели (STT + TTS + LLM одновременно)
- [uv](https://docs.astral.sh/uv/) — для Python-скриптов подготовки моделей
  (ударитель, конвертация FastConformer). Ставится сам при первом запуске,
  если его нет в системе (официальный установщик в `~/.local/bin`); сами
  зависимости скриптов объявлены в их заголовках и тоже ставятся сами
- Доступ в интернет при первом запуске. Что качается само: STT
  (FastConformer, ~460 МБ), TTS (Silero v5, ~91 МБ) и модели ударителя.
  LLM **не качается сама**: какую модель поставить — решает пользователь
  в мастере первого запуска или Настройках → Модель (кнопка «Скачать»
  показывает прогресс и подключает модель без перезапуска; источники:
  релиз `pavel807/jarvis-models` для candle-Qwen3.5-0.8B, каталог Mirai
  для uzu на macOS; переопределяется `JARVIS_MODELS_BASE_URL`)

macOS:
- Apple Silicon (Metal ускоряет LLM/TTS), Xcode с компонентом **Metal Toolchain**
  (`xcodebuild -downloadComponent MetalToolchain`)

Linux:
- Пакет `at-spi2-core` — дерево элементов интерфейса (ui_read/ui_click/
  ui_type/ui_menu); шина org.a11y.Bus поднимается им же
- X11-сессия для управления окнами; на Wayland окна недоступны (музыка,
  громкость, буфер, скриншот через grim работают). Ввод по координатам
  (клики по элементам, Enter после автозаполнения): `xdotool` (X11) или
  `ydotool` + запущенная служба `ydotoold` (Wayland)
- Утилиты по одной на функцию — отсутствующая даёт честный отказ:
  `wmctrl` или `xdotool` (окна), `playerctl` (музыка), `pactl` или `amixer`
  (громкость), `brightnessctl` или `xrandr` (яркость), `notify-send`
  (уведомления), `loginctl` (блокировка), `systemctl` (сон), `gtk-launch`
  (приложения), скриншот — `gnome-screenshot` / `spectacle` / `scrot` / `grim` /
  `import`, буфер — `wl-copy` или `xclip`/`xsel`

Windows:
- Windows 10/11 — больше ничего: PowerShell 5.1 уже в системе

## Запуск CLI (headless)

```bash
cargo run --release -p jarvis-cli
```

Скажите «Джарвис» — прозвучит сигнал, дальше говорите команду или вопрос.

## Запуск GUI

```bash
cd app
bun install
bun tauri dev
```

Приложение живёт в трее (менюбаре): клик — открыть окно, закрытие окна сворачивает
в трей, «Выход» в меню трея завершает. Автозапуск при входе в систему — плагин
autostart (управляется из кода/настроек).

## Интерфейс

Окно 400×820 с нижней навигацией на пять разделов. Всё, что не требует решения
пользователя (пороги тишины, длина ответа, температура модели), в интерфейс не
выведено — эти параметры живут в `settings.toml` и подхватываются на лету.

- **Главная** — реактор Старка: катушки, кольца и ядро живут вместе с ассистентом
  (в покое дышат, на голос вспыхивают, при размышлении по кругу идёт сканирующая
  волна), пауза прослушивания и состояние подсистем человеческими словами.
- **Команды** — команды карточками с понятным описанием действия; редактор
  открывается шторкой (название, слова-триггеры, тип действия, значение).
  Порядок в списке = приоритет, сохранение применяется сразу.
- **Голос** — 29 голосов Silero с группировкой по полу, скорость речи
  и проверка озвучки.
- **Настройки** — понятные переключатели: ответы на вопросы, поиск в интернете,
  проговаривание чисел, звук перед ответом, автозапуск.
- **Ещё** — текстовый чат, обучение «Джарвис» (сэмплы фразы, фоновый шум,
  сборка и проверка модели), помощь и журнал для диагностики.

Тонкая настройка отклика — в `settings.toml`: `silence_timeout_secs` (сколько
тишины VAD speakrs должен подтвердить, прежде чем фраза уйдёт в распознавание),
`max_command_duration_secs` (мягкий предел: пока VAD слышит речь, фраза не
обрезается), `ack_before_llm` (звук-подтверждение перед ответом, по умолчанию
выкл), `wake_threshold` (порог срабатывания wake word).

При открытии раздела блоки появляются каскадом снизу вверх, шапка и панель
вкладок — с началом работы приложения. Анимации отключаются системной
настройкой «Уменьшить движение» (`prefers-reduced-motion`).

### Разработка интерфейса

```bash
cd app
bun run dev   # http://localhost:1420/dev/preview.html
```

`dev/preview.html` поднимает интерфейс с моком Tauri IPC: движок и модели для
правки вёрстки не нужны. Раздел и состояние задаются в адресе
(`?page=commands&scenario=listening`), снимок ровно в размере окна приложения
делает `node dev/screenshot.mjs <файл.png> <url>`. Сценарии описывают фазы
(«слушаю», «думаю», «говорю», действие инструментом), состояние на открытой
странице проверяет `node dev/eval.mjs "<js>"` — нужен Chrome, запущенный с
`--remote-debugging-port=9222`.

## Конфиги и данные

| Путь                  | Назначение                                   |
| --------------------- | -------------------------------------------- |
| `commands.toml`       | голосовые команды                            |
| `settings.toml`       | пороги, LLM, голос (создаётся при сохранении)|
| `models/`             | модели (кэш, не коммитится)                  |
| `train/jarvis*/`      | сэмплы wake word                             |
| `resources/audio/`    | звуки-ответы (ok1-4, reply1)                 |
| `resources/tts_cache/`| кэш синтеза (до 300 МБ, LRU)                 |

Корень данных переопределяется переменной `JARVIS_HOME`. Рабочая папка агента
(от неё считаются относительные пути файловых инструментов) по умолчанию —
домашний каталог; её можно посмотреть и сменить командой `get_cwd`/`set_cwd`,
а из голоса — через `cd` в `shell`. Текущая папка видна в разделе «Главная».

## Тесты

```bash
cargo test -p jarvis-core
```

Покрыты: нормализация текста, Левенштейн/матчинг команд, шаблон ChatML,
сэмплинг (repeat penalty / top-p), фильтр `<think>`, ресемплинг/даунмикс,
а также платформенный слой: разбор вывода `wmctrl`/`xrandr`/`.desktop`,
`Get-StartApps`, `playerctl`, base64 для PowerShell — эти тесты чистой
логики идут на любой ОС, не только на целевой.

## Проверочные примеры

```bash
# верификация FastConformer: mel/энкодер/CTC/RNNT поэтапно против ONNX-эталона
# (фикстуры готовит tools/fastconformer_fixtures.py)

# бенчмарк этапов Metal vs CPU

# сравнение мужских голосов Silero на одинаковых фразах (WAV в build/)

# бит-точность синтеза против PyTorch-эталона

# озвучка с ударениями и без (на слух)
```

## Сборка дистрибутива

```bash
scripts/build_macos.sh   # build/Jarvis-<версия>.dmg
```

По умолчанию тяжёлые модели в `.app` не встраиваются — приложение скачивает их
при первом запуске в `~/Library/Application Support/Jarvis/models`. Внутри
архива — звуки, конфиги и крошечные wake word-модели. Офлайн-сборка со всем
внутри:

```bash
JARVIS_EMBED_MODELS=1 scripts/build_macos.sh
```

Релиз с моделями (silero + Qwen3.5) для `pavel807/jarvis-models` собирается
`scripts/pack_models.sh` — готовые `build/models/*.tar.gz` загружаются в релиз
`models-v1`.

## Известные ограничения

- LLM-загрузка при старте занимает память заранее; на 8 ГБ машинах возможны
  свопы.
- Ответы LLM озвучиваются по предложениям; отмена («замолчи») срабатывает
  между токенами.
- Для сборки `.app` нужны иконки всех размеров: `cd app && bun tauri icon icons/icon.png`.
- Linux и Windows: платформенные реализации покрыты тестами чистой логики
  (разбор вывода wmctrl/playerctl/tasklist, словари, base64 — гоняются на
  любой ОС) и компилируются под свои цели в составе workspace, но живого
  прогона на этих ОС пока меньше, чем на macOS. Найденные шероховатости
  видны сразу: каждый отказ — с причиной и подсказкой, поэтому молчаливых
  ложных успехов нет.
